# Dota 2 录像复盘

**项目版本：0.21c**

面向 Dota 2 比赛录像的本地复盘工具。项目围绕 `.dem` 录像解析英雄轨迹、眼位、开雾、神符、BP 与经济等数据，并提供比赛浏览、趋势分析和证据型复盘能力。

## 项目状态

当前项目处于本地开发和验证阶段。GitHub 仓库现阶段仅用于展示项目说明，**目前不执行部署**，也不提供可公开访问的在线服务。

## 计划中的 Docker 部署方案（暂不执行）

未来如进入部署阶段，计划以 Docker 容器化方式交付，并通过 Docker Compose 编排应用及其依赖：

1. **应用镜像**：编写多阶段 Dockerfile，在构建阶段安装前端依赖并生成静态资源，在运行阶段安装 Python 依赖并启动 FastAPI；前端静态资源由应用或独立 Web 服务提供。
2. **服务编排**：使用 Docker Compose 管理应用容器与 MySQL 服务（或连接受控的外部 MySQL）。容器间使用内部网络通信，数据库端口不直接暴露到公网。
3. **持久化数据**：为 MySQL 数据目录和应用需要保留的数据配置命名卷或受控挂载目录，并制定定期备份与恢复流程。比赛录像和缓存应单独规划容量及保留周期。
4. **运行配置**：通过部署环境变量或 Docker secrets 注入数据库凭据及可选模型服务密钥；敏感 `.env` 不进入镜像和 Git 仓库。应用容器以非 root 用户运行，并配置健康检查与合理的资源限制。
5. **入口与安全**：在 Compose 中增加反向代理容器处理 HTTPS、域名和访问日志；配置认证与访问控制后再开放外部访问，限制管理接口及数据库网络权限。
6. **发布流程**：固定基础镜像和依赖版本，构建带版本标签的镜像；先在隔离环境验证启动、数据迁移、备份恢复和回滚，再决定是否发布到正式环境。

以上仅为后续 Docker 部署的规划说明。Dockerfile、Compose 配置、部署平台、域名、认证策略及数据迁移方案尚待部署阶段设计和验证；**当前阶段不构建或启动部署容器、不创建云资源、不迁移数据库，也不发布在线服务**。

## 当前本地开发方式

本地开发所需源码与配置模板保留在开发工作区。开发者可在准备好的 Python 环境中安装 `requirements.txt`，并在 `frontend/` 安装 npm 依赖后启动 API 和前端开发服务器。具体命令、环境变量和数据准备以本地源码及 `.env.example` 为准。

比赛录像、数据库、缓存和密钥属于本地或受控运行数据，不应上传到公开仓库。
